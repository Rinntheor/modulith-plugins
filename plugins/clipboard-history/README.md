# 剪贴板历史

复制过的东西会留在这里：按时间倒序排好、能搜索、能置顶、能删掉，点一下就能重新放回剪贴板。

## 功能

| 功能 | 怎么用 |
| --- | --- |
| 记录 | 不用做任何事 —— 复制（`Ctrl+C`）之后它会自己出现在列表最上面 |
| 贴回去 | 悬停某条，点「复制」 |
| 搜索 | 在搜索框里打字（会在**完整正文**里搜，不只是列表里显示的预览） |
| 置顶 | 悬停某条，点「置顶」。置顶的条目不会被自动清理 |
| 删除一条 | 悬停某条，点「删除」（会二次确认；置顶的也能手动删） |
| 清空 | 右上角「清空」（保留置顶的）／「全部清空」（连置顶一起删，有确认） |
| 暂停 | 右上角「暂停」。暂停期间复制的东西不会被记录 |
| 记录图片 | 默认**关闭**。设置里打开「也记录图片」之后，复制的图片会带一张缩略图 |

标题右边那个小徽标是**采集状态**，一直都在：`记录中` / `已暂停` / `已关闭` / `无法采集`。
不用点开任何东西就能看出它现在到底在不在记。

同一条内容被重复复制，不会堆出第二行 —— 它会回到最上面，并更新时间。

## 隐私（这一节请读完再看功能）

这个插件需要 `clipboard-monitor`，那是权限表里**风险等级最高**的几项之一：它能看到你在这台电脑上复制的**任何**东西，包括密码、验证码、私钥。

因此先把它的边界说清楚：

| | 事实 |
| --- | --- |
| 存在哪 | 只在这台机器上：插件的 SQLite 数据库与图片目录（Modulith 的插件数据目录下）。**不上传任何地方** —— 这个插件没有声明网络权限 |
| 加密吗 | **不加密。** 就是明文文件。任何能读你这台机器上这个账户的文件的人都能读到 |
| 谁标记的会跳过 | 密码管理器一类程序会在剪贴板上放 Windows 约定的三个标记（`ExcludeClipboardContentFromMonitorProcessing` 等），宿主看到就**一个字节都不读**。但**这只是约定**：不合作的程序放上去的任何东西，宿主没有办法分辨 |
| 因此列表完整吗 | **不完整。** 被标记的内容不会出现，也没有任何提示 —— 不要用"列表里没有"推断"我没有复制过" |
| 什么时候在记 | 只在**应用运行期间**。宿主每 800 ms 看一次剪贴板，因此 800 ms 内复制两次只会记下后一次；应用关掉监测就停了 |
| 一次能记多长 | 文本最多 64 KiB，超出的部分被截断，而且**没有标志位**。因此一条很长的记录可能不完整 |
| 图片 | 默认不记。开启后每张最多 8 MB；超过这个体积的图（例如一张 4K 截图，宿主自己编码时很容易越线）会显示「图片过大，没有保存」，文本部分照常记 |
| 怎么关掉 | 面板右上角「暂停」（临时，重开插件即恢复）；设置 → 插件设置 → 剪贴板历史 → 关掉「启用采集」（持久）；「清空」删掉已经存下来的 |

**卸载插件不会自动删除这些数据**（宿主的插件数据默认保留，以便重装同一个插件时拿回来）。要清掉用面板上的「清空」，或者走宿主自己的插件数据清理入口。

## 保留多久、占多大

自动清理在**启动时**与**每次记录之后**都会跑一遍，规则是（都可以在设置里改）：

| 规则 | 默认 | 说明 |
| --- | --- | --- |
| 最多保留多少天 | 30 天 | 超龄的条目连同它的图片一起删掉 |
| 最多保留多少条 | 1000 条 | 超出后从最旧的开始删 |
| 图片总量上限 | 256 MB | 所有图片加起来超了就删最旧的图片（**条目本身保留**，只是没有缩略图了） |
| 数据库体积上限 | 64 MB | 兜底：正文也可能很大（单条最多 64 KiB），超过就从最旧的未置顶条目删起 |

**置顶的条目不被任何一条规则删除。** 上表里的"条数"说的是"未置顶部分保留多少条"。
唯一的例外是上表最后两行那种极端情况：置顶的图片自己就把预算吃满了，那时会摘掉最旧的置顶图片（**只摘图片，不删条目**），并在面板上说明一句。

## 已知的取舍

### 「复制回去」不会被再记一遍

这是这个插件最容易写错的地方。写入剪贴板本身会让宿主交付一次变化事件，如果照着记就会得到一条重复条目，而重复又会让下次复制再触发一次 —— 一个自我维持的回声。

做法是：**写入成功之后记一份回执（时间 + 写出去的那段文本），下一次观察与它匹配就丢弃，每份回执只用一次。** 用一次是有意的：同一个人连续复制两次同一段文本是常事，第二次是他的真实动作，该被记下来。

细节与边界写在 `index.js` 的「自我写入的回执」那一节。

### 800 ms 的粒度是真的

宿主每 800 ms 看一次剪贴板序列号，因此 800 ms 内复制两次只会得到后一次 —— 中间那一次**永久丢失**，而且没有任何症状。事件里的时间戳也是"宿主观察到的时刻"，不是"你按 `Ctrl+C` 的时刻"。

### 一万条也要能用

三件事一起做到：

* 列表是**窗口化**的（只渲染视口附近的行，其余用占位块撑着），行高是量出来的而不是估的；
* 取数是**游标分页**（一页 200 条），不是 `OFFSET`；
* 正文与预览**分开存**（列表只取前 200 字符，完整正文只在点「复制」时按 id 取一行）。

## 它用到的宿主能力

| 权限 | 用来做什么 |
| --- | --- |
| `storage` | 读设置项（`ctx.settings`） |
| `plugin-data` | 历史存在 `ctx.db`（每插件一个 SQLite），图片存在 `ctx.dataDir` |
| `clipboard` | 「复制回去」写一次剪贴板 |
| `clipboard-monitor` | 订阅剪贴板变化、读格式与图片 |

`clipboard` 与 `clipboard-monitor` 是**两项独立的权限**：前者管"插件调一次、读写一次"（前端强制，浏览器 API 本来就在同一个文档里），后者管"用户在**所有程序里**复制的每一样东西"（后端强制，`high` 风险）。这个插件两项都要，因为观察之外还要能写回去。

`ctx.storage` 没有用来存历史：它是"一键一个 JSON"，单值 1 MB、总量 8 MB，装一个会增长的列表是错的形状。历史在 `ctx.db` 里，因为它能 `query`、能 `LIMIT`、能在 1 万条上让 SQLite 做分页。

## 版本前提

清单里写的是 `"engines": { "modulith": ">=1.6.4" }`。

**这个下限不能再低。** 本插件依赖的 `clipboard-monitor` 权限与 `ctx.clipboard` 的
`canMonitor / subscribe / readFormats / readImage` 都是 **1.6.4** 才有的。更旧的宿主
（包括 1.6.3）不会给出任何兼容性提示，而插件在里面根本跑不起来：`canMonitor()` 恒为假，
订阅与读图片都不可用。

因此**宿主 1.6.4 必须先正式发布，本插件才能上架**；在此之前它只能以开发链接的方式在
本机试用。若最终发布时宿主改了版本号，这里的字符串必须跟着改**并重新打包** —— 包变了
就升插件版本，不要在原版本号上覆盖产物。
