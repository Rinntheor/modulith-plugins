# 看板

把要做的事按「待处理 / 进行中 / 已完成」三个列表摆开，拖动卡片就能挪动它的状态 —— 不用先想清楚它属于哪个分类，也不用给它取一个像样的名字。另有一页「速记」，想到什么先记下来，再逐条丢进看板。

## 它解决什么问题

待办清单只能回答「还有哪些事没做」。看板回答的是「每件事现在走到哪一步了」：哪几件已经在手上、哪几件堆着没动、哪几件真的做完了。这个区别在你手上超过五六件事的时候就变得明显了 —— 清单里一长串没有差别的条目，看板里一眼能看出堵在哪一栏。

## 怎么用

新建卡片
  点任意列表底部的「添加卡片」，写下要做什么，回车即可。输入框下方可以直接选优先级、重复方式与截止日。
  快捷键：Ctrl + N 在第一栏打开新建输入框。第一次打开时是空白页，中间有一个输入框可以直接写下第一件事。

设截止日
  常用日期做成了四个按钮：今天 / 明天 / 本周末 / 下周一，点一下就好，不用翻日历；
  需要别的日期再用右边的日历自选，「不设」用来清除。编辑器里还有一个「顺延一天」。
  卡片上的日期标签本身也能点：点一下把截止日往后顺延一天，聚焦卡片后按 M 键同效。
  一张卡片没设日期时，它的位置会显示一个虚线「未设日期」，点一下即设为今天。

挪动卡片
  按住卡片拖到别的列表，松手即落位。拖动时有一条横线标出它会被插到哪两张卡片之间，
  浮动的小卡片上还会写「移到「进行中」」这样的目标提示；落到新位置后卡片会闪一下底色，
  免得「到底动没动」要靠猜。
  键盘操作：聚焦卡片后按 Alt + 左/右方向键移到相邻列表，卡片右下角也有「移到下一个列表」按钮。
  桌面读屏用户会听到一句「已移动到「进行中」」。

  说明一下顺序规则：列表里的卡片按「未完成 → 优先级 → 截止日 → 手动顺序」排。
  因此手动拖动只在同一优先级、同一截止日的卡片之间改变先后 —— 这是刻意的，
  不然「高优先级」这个字段就没有意义了。拖动时那条指示线指的就是卡片真正会落到的位置。

完成与编辑
  卡片左下角第一个小按钮是「标记为已完成」，第二个是「编辑」。
  键盘上：Tab 走到卡片后按回车就能打开编辑器，在卡片上双击也行。
  编辑器里可以改标题、补充说明、优先级、重复方式、截止日，以及它属于哪个列表。
  把卡片拖进名字里带「完成」两个字的列表，会自动标记为已完成；拖出来会自动取消。

重复任务
  把重复方式设为每天 / 每周 / 每月之后，勾选完成不会让它停在那里，而是自动把截止日推到下一次，
  卡片继续留在原地。基准是「当前日期」而不是原截止日 —— 逾期很久的任务被点完成时，
  不该一下子生成一串过去的日期。

找东西
  搜索框（Ctrl + F）同时匹配标题和说明。左边三个筛选按钮：全部 / 已逾期 / 高优先级，
  右上角写着「显示 N / M 张」。「已完成 N」按钮里可以隐藏已完成卡片，或者一次清掉它们。

删除与撤销
  删除卡片后，界面底部会留 8 秒的提示条，上面有「撤销」。超过 8 秒提示条收起，删除就不可挽回了。
  删除列表同样可以撤销，并且连列表里的卡片一起恢复。最后一个列表不会被删掉。

整理列表
  每个列表右上角的「⋯」里有全部列表操作：重命名、左移一栏、右移一栏、折叠、删除。
  列表名左边的点阵是拖动手柄 —— 按住可以把整栏拖到别的位置，落点会画一条竖线；
  不想拖就用菜单里的左移 / 右移。
  折叠后列表变成一条竖条，窄窗口里很实用。最右侧的「添加列表」可以按自己的流程加一栏，
  例如「待确认」「下个版本」。

  工具栏上的「列表」按钮里有一个「恢复默认列表」：把看板恢复成「待处理 / 进行中 / 已完成」三栏。
  它**不删除任何卡片** —— 已经完成（或原本在「完成」栏）的进「已完成」，原本在「进行中」的进
  「进行中」，其余进「待处理」。同名的栏会被复用，不会出现两个「已完成」。

速记
  顶部的「速记」标签是一页独立的白纸，和看板分开保存。「一行一件事」是这里唯一的要求：
  右边会把每一行列出来，每行后面两个按钮 —— 左边那个可以选一个列表直接把这行变成卡片
  （会自动去掉 `-`、`1.`、`[ ]` 这类列表前缀），右边那个只复制这一行。
  这样「随手记」到「真正排进看板」之间不需要再复制粘贴一遍。

到期提醒
  右上角的铃铛控制它。开启时（默认开启），打开看板或切回看板的那一下，如果有卡片已逾期或今天到期，
  会发一条应用内通知，正文里列出前几项。同一天内同样的一批内容只提醒一次 ——
  重复刷屏的结果是用户不再看通知。跨天后会重新提醒。没有需要提醒的事就不会弹。

## 用到的权限

只有三项，都是最低限度：

  storage
     看板数据、速记草稿、提醒开关存在插件自己的私有存储里（应用数据目录下按插件 ID 分隔的位置）。
     卸载插件时这些数据会一并删除。这是唯一持久化数据的地方，没有它这个插件无法工作。

  notification
     到期 / 逾期的提醒，以及「清除已完成」这类不可撤销操作的结果说明。只出现在应用内，
     关掉应用就无法提醒。铃铛关掉后不再发送任何提醒。

  plugin-communicate
     宿主支持窗口内分屏，两半可以同时打开同一个看板。这个权限只用来在保存成功后向另一个实例
     广播一句「我改过了」，好让两边保持一致；同时写盘前会先比对版本号，避免后写的一方静默覆盖
     先写的一方。用它做的只有这一件事，它不会把数据发往任何地方。

没有申请任何原生能力：不能启动程序、不读本机文件、不访问网络、不碰剪贴板。
所有提示一律画在界面内部，就算去掉 notification 权限，功能也不受影响，只是不再弹提醒。

## 数据存在哪里

看板数据是一个键（`board`），速记是另一个键（`draft`），提醒开关是第三个（`prefs`）。
分开的理由：速记是高频小改动、看板是低频大改动、开关又是另一回事，
混在一个键里会让改一个字就重写整份看板数据。看板本身的数据结构版本没有变，
因此用旧版本插件打开新数据不会触发「来自更新版本」的保护提示。

本插件的取舍：整个看板是「一个键一份文件」。好处是任何一次移动、编辑都是一次原子写入，
不会出现「卡片挪过去了但列表顺序没更新」的半截状态；代价是这几十 KB 的数据每写一次都是
整份重写。卡片数量在数百张以内时这个代价可以忽略；如果你的看板有上千张卡片并且感到卡顿，
那说明该拆成多个键了 —— 这条边界写在这里，而不是藏起来。

## 已知边界

  拖放是自己实现的。宿主为了接收系统拖入而开启了 Tauri 的拖放拦截，WebView 内的
  HTML5 拖放整体不可用，所以插件用 Pointer Events 自己实现了拖动。因此拖动只在本插件
  自己渲染的卡片之间有效，不能把别的应用里的内容拖进来看板。

  手动顺序只在同一优先级、同一截止日之内生效，原因见上面「挪动卡片」。

  分屏时两个实例各自渲染。它们通过保存时的版本号比对避免互相覆盖：如果另一半刚保存过，
  这一半的这次改动会保留在界面上并给出提示，需要你重新操作一次。这是刻意的选择 ——
  自动合并两份同时改动过的看板很容易得出一个谁都没想要的结果。

  只有应用内通知，没有系统级通知。应用关掉时无法提醒；提醒发生在打开看板的那一刻，
  不是「到点准时弹」。

  没有归档。已完成但不想删的卡片，建议自己加一个「已归档」列表放进去。
