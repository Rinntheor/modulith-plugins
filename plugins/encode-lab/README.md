# 编码与哈希工具箱

九件常用的小工具放在一处：编码转换、哈希与密钥计算、令牌解码、时间戳互转。
全部在你的电脑上完成，输入的内容不会发送到任何地方。

## 给谁用

写代码、对接口、查日志的人。典型场景：接口返回了一串 Base64 看不懂、要核对一段
内容有没有被改过、拿着一串 JWT 想知道里面写了什么、日志里只有一个时间戳。

## 九个工具

| 工具 | 做什么 |
| --- | --- |
| Base64 | 文本与 Base64 互转；顺带给出 Base64URL 写法 |
| URL 编码 | 百分号转义；编码方向同时给出「严格」与「保留结构字符」两种结果 |
| 十六进制 | 文本与十六进制字节互转；给出连续、大写、带空格、带 0x 前缀四种写法 |
| HTML 实体 | 把 & < > " ' 转成实体，或反过来还原 |
| Unicode 转义 | 文本与 \uXXXX 互转；也支持 \u{XXXXX} 码点写法 |
| 哈希 | SHA-1 / SHA-256 / SHA-384 / SHA-512，一次全给 |
| HMAC | 带密钥的消息认证码，算法与输出写法可选 |
| JWT | 拆开令牌看头部与载荷，并解析有效期 |
| 时间戳 | 时间戳与日期时间互转 |

前五个工具都有「编码 / 解码」两个方向，用右上角那对按钮切换。

## 怎么用

1. 在上方选一个工具。
2. 在左边的框里输入或粘贴内容。右边立刻给出结果，不用点按钮。
3. 每个结果都有两个按钮：「复制」把结果放进剪贴板；「用作输入」把结果填回左边的框，
   接着做下一步 —— 比如「文本 → Base64 → URL 编码」这种连续转换。

几个值得一提的细节：

- Base64 与十六进制都按 UTF-8 字节处理。中文、emoji 都能正确往返，
  不会出现在别的工具里常见的那种「一遇到中文就报错」。
- 十六进制解码时会自动忽略空格、换行和 0x 前缀，所以从各种地方粘过来的写法都能直接用。
- 时间戳工具会看输入的形状自己判断：纯数字按时间戳解释，其余按日期时间解释。
  数字大于 1e11 视为毫秒，否则视为秒 —— 界面上会写清这一次是按哪种理解的。
- JWT 工具会额外把 iat / nbf / exp 这几项翻译成本地时间，并直接告诉你令牌
  是不是已经过期。

## 用到的权限

只有一项：

| 权限 | 用来做什么 |
| --- | --- |
| storage | 记住当前选的是哪个工具、你输过的内容草稿、以及结果写法这类偏好 |

没有申请网络相关的权限 —— 这里没有任何一处会发起请求，所有转换与计算都是本机完成的。
也没有申请文件相关的权限 —— 本插件不读写任何文件。

关于复制按钮：它用的是应用界面自带的剪贴板接口，不经过宿主提供的剪贴板服务，
因此这里没有申请 clipboard 权限。若该环境不允许，复制会失败并提示你手动选中复制。

## 边界

写在前面，免得你在某个时刻以为它坏了：

- JWT 工具只解码，不验签。它不会、也无法告诉你这个令牌是否被篡改过、由谁签发。
  需要确认这些，必须用签发方的公钥真正验一次签名。
- HMAC 的密钥只在本次使用期间留在内存里：不写磁盘、不进日志，关掉这一页或重启应用后
  需要重新填写。这是刻意的 —— 一个用来验证消息来源的密钥被存进磁盘，就等于多了一份
  长期凭证。
- 哈希与 HMAC 由系统提供的计算接口完成。极少数环境下该接口不可用，那时会明确告诉你
  无法计算，而不是给出一串假的摘要。
- SHA-1 已经可以被用来人为制造碰撞。它仍然适合校验文件有没有传坏，
  不适合用来做签名。
- 输入超过 20 万字符时不再随输入自动计算，需要点一次「立即计算」。
  这是为了避免每敲一个键都跑一遍全量转换。
- 输入的内容不会被写进日志。
