# 影像元数据工坊

**查清一张图里到底有什么，抹掉你不想留下的东西，留下你想要的署名 —— 以及一条能追责的链路。**

给用 ComfyUI、Stable Diffusion、NovelAI 这类工具出图的人用。它们会把**完整的提示词、
工作流、模型名、随机种子**写进 PNG 的文本块里，而你在论坛、群聊、委托交付时通常
并不想把这些一起发出去。

这个插件做四件事，每一件都单独可用：

| | 做什么 |
| --- | --- |
| **检视** | 把图里的每一个元数据块摊开给你看：生成器参数、EXIF、XMP、来源凭证，连被旁路的工作流节点都标出来 |
| **批量清理** | 按你勾的策略**无损**抹除痕迹，并追加作者、版权、联系方式等信息 |
| **水印设计** | 可见水印（署名 + 威慑）与写在像素最低位的隐形追踪水印（取证） |
| **追踪台账** | 每一份成品留一条记录。事后拿到一张流出的图，能查出当初发给了谁 |

所有处理都在本机完成。图片不会被上传到任何地方，插件也不联网。

---

## 快速开始

1. 打开侧边栏的「影像元数据工坊」。
2. **检视**页点「选择目录」，挑一个装着成图的文件夹 —— 它会自动解析第一张，
   把提示词、模型、LoRA、采样参数列出来。
3. 切到**批量清理**页，确认清理策略（默认已经勾好了该勾的）。
4. 填上作者与平台（在**设置**页填一次即可，之后各处共用）。
5. 点「选择输出目录」，再点「开始处理」。

成品会写到输出目录，文件名形如 `原名-AT-20261007-0001-A0E8.png` —— 中划线后面
就是这一份的追踪编号。

## 检视：先给结论，再给证据

打开一张图，你会先看到**一句话结论**：这是 ComfyUI 生成的、带着完整的生成参数。
然后是十几个最常看的参数（步数、CFG、采样器、调度器、随机种子、底模、VAE、
CLIP skip），再下面是提示词原文，最后才是「全部块 / EXIF / XMP / 原始 JSON」
这些给排查用的东西。

**结论分三档，而不是"干净 / 不干净"：**

| 徽标 | 含义 |
| --- | --- |
| **有痕迹** | 含生成参数 / EXIF / XMP / 来源凭证。这些通常不是你想留的 |
| **仅标注** | 只有文本块（作者、版权、软件署名一类）。可能是你自己加的 |
| **干净** | 一个元数据块都没有 |

为什么分出中间那一档：这个插件**自己会往成品里写**作者、版权、联系方式、追踪编号。
把那些也算成"有痕迹"，你拿刚导出的成品回来查就会看到"这张图有痕迹" ——
那是工具在指控自己。而"仅标注"如实说出"这里有你写的元数据，但它不是生成痕迹"。

几个刻意的设计：

- **正向与负向提示词靠遍历工作流得出，不是"第一个 / 最后一个"。** ComfyUI 的
  `prompt` 是一张节点图，正负提示词是通过 `positive` / `negative` 两条链接分别
  连到采样器的。这个插件沿着链接走，因此有多段提示词、有 `ConditioningCombine`、
  有 ControlNet 的图也能给对。**把正负弄反的这个插件就没有价值**，所以这一步
  做得比看起来需要的更认真。
- **被旁路的节点会被标出来。** ComfyUI 的工作流里 `mode: 4` 的节点没有参与生成
  （画布上是紫色的）。只看工作流会得出"这张图用了放大模型"这种错误结论。
- **`IDAT` 之类的结构性块默认折叠。** 一张 4.5 MB 的 PNG 有 70 个 `IDAT`，而真正的
  元数据只有 2 个。全列出来会把重点淹掉。

## 批量清理：默认那条路是无损的

这是本插件最需要理解的一点。

**默认（不勾「重编码像素」）走的是容器重建。** 它只把文件的结构重排一遍 —— 丢掉
你选中的块、写回方向与追加的信息 —— 而**像素数据逐字节原样搬运**。因此：

> 除被删掉的元数据之外，成品与原图**逐字节相同**。颜色、压缩率、像素一个都没变。

这条路经真实文件验证过：对 4 张 ComfyUI 出的 PNG，不丢任何块时重建的结果与原文件
**逐字节相同**；丢掉 `prompt` 与 `workflow` 之后，`IDAT` 依然逐字节相同。

**勾上「重编码像素」走的是另一条路**：像素经过一次解码 → 绘制 → 编码。它更彻底
（能顺手洗掉藏在像素排列里的隐写），代价是像素可能被重新采样、ICC 与全部元数据都会
丢失。**打水印必然走这条路**，因为文字要画在像素上。

### 默认保留的东西

三样东西默认**不**抹掉，因为它们不是隐私，而抹掉它们会把图弄坏：

- **ICC 色彩描述文件** —— 丢掉它，广色域作品在色彩管理正确的查看器里会明显偏色。
- **物理尺寸（DPI）** —— 它影响打印尺寸与部分排版工具的默认缩放。
- **EXIF 方向** —— 这是最容易踩的一个：方向是元数据，但它**决定画面怎么摆**。
  直接删掉，一张竖拍的照片在查看器里会变成横的。勾着「保留方向」时，插件会写回
  一个只含方向一项的最小 EXIF。

### 追加信息

填了作者、平台、主页、联系方式、授权协议、订单号、买家之后，成品里会多出这些
文本块：`Author` / `Copyright` / `Contact` / `Source` / `License` / `Description` /
`art-trace` / `Software`。**空字段不写。**

`art-trace` 那一块是机器可读的（`v=1|id=...|a=...|p=...|d=...`），键名与隐形水印的
载荷完全一致 —— 因此从元数据里读到的编号与从像素里读到的可以对上。

> 为什么不写进 `Comment`：NovelAI 用 `Comment` 装生成参数的 JSON。把作者信息写进去，
> 会让下一个用任何识图工具看这张图的人看到一段"看起来像生成参数、但解析不出来"的
> 东西 —— 那比没有更坏。

## 水印设计

### 可见水印

用多行文本，第一行是主标题。每行都可以用占位符：

| 占位符 | 含义 |
| --- | --- |
| `{author}` | 作者名 |
| `{platform}` | 平台 |
| `{profile}` | 主页链接 |
| `{contact}` | 联系方式 |
| `{license}` | 授权协议 |
| `{id}` | 本次的追踪编号 |
| `{date}` | 日期（`yyyyMMdd`） |
| `{buyer}` | 买家 / 客户 |
| `{order}` | 订单号 |
| `{extra}` | 备注 |

**认不出的占位符会原样画出来**，而那是在提醒你名字打错了。

可以调：位置（四角 + 底部居中）、样式（描边文字 / 圆角底板）、主行字号、副行比例、
边距、不透明度，以及墨水颜色。

**墨水颜色「自动」会测量水印底下那块区域的亮度**：画面偏浅就画深色字、偏深就画浅色字。
因此同一套参数在浅色与深色作品上都能看清。

**「用一张图预览」走的是与成品完全相同的排版与绘制代码**，只是缩小了尺寸、不写隐形
水印。预览下方还会给出三个量化指标：墨水判定结果、LSB 信道占用率、文案占画面高度的
比例 —— 后两个超出合理范围时会直接提示你。

### 隐形追踪水印

写在每个像素 **RGB 三个通道的最低位**，肉眼不可见（每个通道的改动量 ≤ 1）。内容
由你自己定义，写成 `k=v|k=v` 最便于事后查阅。

「冗余份数」是整份载荷在像素里铺几遍。**抗裁切能力来自"载荷铺满图形"**：

- 铺得多 → 裁掉一部分仍能读出一份完整的；
- 但载荷相对图像越大，改动面也越大，越容易被有损转码冲掉。

因此预览里那个**占用率**值得看一眼：它低（比如 1%）意味着裁掉一个角就可能把整份
载荷一起裁掉。

> **诚实地说清楚边界：** LSB 水印只在**无损链路**里可靠 —— PNG 转存、复制、无损裁剪
> 都没问题。**转成 JPEG、缩放、截图会把它冲掉。** 因此请务必把 `{id}` **也放进可见
> 水印**：可见编号 + 台账才是可靠的追责链路，隐形水印是锦上添花的隐蔽手段。

## 追踪台账

每一份成品都会在台账里留一条记录：追踪编号、输出文件名、输出目录名、源文件名、
作者 / 平台 / 订单 / 买家 / 授权、可见水印实际渲染出来的那几行、隐形载荷全文、
成品与源文件的 SHA-256、尺寸、体积变化、时间。

**拿到一张流出的图怎么用：** 在台账页点「检视一张图」，选那张图。插件会从像素最低位
里读出编号，然后**直接去台账里查** —— 查到了就把它当初发给了谁列出来；没查到会明确
告诉你「读到了编号，但台账里没有这个记录」。

台账存在**插件私有的 SQLite 数据库**里（不是键值存储），因此记录多了也能按编号、
文件名、作者、订单号搜索，并能按时间分页。导出支持 CSV（带 BOM，Excel 打开不乱码）
与 JSON（含导出时的筛选条件）。

**序号会持久化，而且生成前会查一遍台账** —— 因此同一个编号不会被发给两张不同的图。
那正是台账唯一要防的事。

## 权限说明

这个插件申请五项权限，每一项都真的在用：

| 权限 | 用在哪 |
| --- | --- |
| `filesystem-read` | 读取**你在原生对话框里选中**的图片文件，以及列出你选中的目录 |
| `filesystem-scoped` | 把成品写进**你选定的输出目录** |
| `plugin-data` | 台账数据库（每插件一个 SQLite 文件） |
| `storage` | 保存你的设置（身份信息、水印参数、清理策略、编号序号） |
| `notification` | 批量处理完成时提醒一次 |

关于文件访问，有三件事值得写清楚：

1. **插件拿不到任何路径。** 唯一能产生一次文件访问的动作是**你在宿主弹出的原生
   对话框里选中了某个文件或目录**。插件能提供的只有对话框标题与扩展名过滤器 ——
   两者都只影响你看到什么，不影响你能选什么。没有 `open(path)` 这种接口。
2. **授权是会话级的。** 它绑在"这个插件的这块界面"上：界面关掉、插件停用、应用退出，
   授权就失效。因此不存在"这个插件去年拿到过一个目录的权限"这种事。
3. **它删不掉你选的那个目录本身。** 最坏情况是删掉插件自己写进去的东西。

## 已知限制

写在这里而不是等你自己撞上：

- **支持的清理格式：PNG、JPEG、WebP、GIF。** BMP / TIFF / AVIF 能识别格式并给一句
  说明，但还不能清理它们的元数据。
- **压缩过的文本块（`zTXt` / 压缩的 `iTXt`）在列表里不展开内容**，只报告体积。
  清理时它们会被原样搬运或按你的策略丢掉，不会损坏。
- **EXIF 只跟随 IFD0 / Exif / GPS / Interop / IFD1 五处**，MakerNote 当作不透明数据
  显示体积。C2PA 的检测是启发式的。
- **打水印会丢失 ICC。** 像素经过画布重画，ICC 描述的是"原来的那些数字该怎么解释成
  颜色"，对重画之后的像素不再成立。这是重画像素的固有代价。
- **`{id}` 的随机段不是密码学强度的。** 它防的是"照着格式仿造一个编号"，不是防伪。
  真正防伪的是台账里的 SHA-256。
- **隐形水印在透明区域不写** —— 只改 RGB、不改 alpha。改 alpha 会让图在透明背景上
  出现可见噪点。

## 它需要什么样的宿主

本插件用 `ctx.files`（宿主提供给插件的、**用户当场授权**的文件读写通道）。
`manifest.json` 里声明的下限是**带这个能力的宿主版本**。

在不带它的宿主上，插件仍然能装、能打开，界面会明确写出"当前宿主不提供
`ctx.files`"以及该去哪里确认版本 —— 而不是留下一块白板。
