# 打字练习

逐字符判定的打字练习器：中英文语料可选，实时显示速度与准确率，练完留下记录与走势，还能看出自己最常按错哪几个键、以及"想打 A 却按了 B"这种固定误触。

## 它解决什么问题

打字的速度瓶颈很少是"手不够快"，而是"改错花掉的时间比打字还多"。所以这个插件把重点放在**看得见错在哪**：每个字符的对错就地标出，错过的位置留着标记直到你改对；练完之后，"分析"页会攒出一张键盘热力图和一张误触对照表 —— 那比一个孤零零的 WPM 数字有用得多。

## 怎么用

开始练习
  选一段语料（中文 / 英文，或按长度挑），点一下打字区就开始打字。**计时从你敲下第一个键开始**，
  不是你打开这一页的时候 —— 读题的时间不该算进速度。

看反馈
  打对的字符正常显示，打错的字符是红字加浅红底并划线，**当前要打的位置有一条竖条光标**。
  退格改对之后，红色标记会消失。长文本会跟着光标自动滚动，不必自己去拖滚动条。
  打字区里**不能用鼠标选中文字**：这是练习，选中没有用途，拖动选择还会让逐字符的底色乱跳。

完成与结果
  打到最后一个字符（段落末尾的空格不计）自动结束，给出速度、准确率、用时与按错次数。
  速度用的是通行定义：**正确字符数 ÷ 5 ÷ 分钟**；准确率是正确字符占全部输入的比例。
  中途想停，点「结束本轮」—— 它会按当前进度结算成绩，但这轮**不计入"最好成绩"**，
  在历史里也会标注"中途结束"。想重来点「重来」。

分析（第三个标签页）
  这是用来回答"我到底卡在哪"的：

    总体          累计练习次数、最近若干次的平均速度与平均准确率，以及「按键出错率」
    想打的和实际按下的   例如「想打 D，实际按了 S」出现了多少次 —— 这类固定误触比
                  "错得最多的字符"更能说明问题，因为它指向的是某根手指的系统性偏移
    你最常按错的键    一张美式键盘布局的热力图，颜色越深按错越多，键上写着次数
    速度走势        最近十次
    常打错的字符    累计计数

  中文输入法打拼音时，字母按错同样会记在热力图里。

历史
  最近 50 次记录的明细表（时间、段落、速度、准确率、用时、错按）与走势图。
  记录最多留 50 条，超出后自动丢掉最旧的。清空历史需要二次确认。

设置（练习页底部，平铺）
  四项：**显示实时速度**、**严格模式**（打错了必须先退格改对，光标才会继续前进）、
  **打字音效**（0–100 的音量滑块，默认 100）、以及语料语言。

添加 / 导入练习文本
  点「添加 / 导入练习文本」可以：

    粘贴       把任何文本贴进去，20–20000 字
    从文件导入  选一个本机纯文本文件（.txt / .md 等，400 KB 以内）

  保存时会让你起个名字，之后它和其他语料一样以标签形式列在那里，可以随时切换或删除，
  最多保留 30 份。导入不申请任何文件系统权限 —— 用的是浏览器自己的文件选择框，
  文件内容只在本地读一下，不会上传、也不会在磁盘上留副本（正文存进插件自己的存储）。

## 音效

打字音效是**用 WebAudio 现场合成的短促脉冲**，插件包里没有任何音频文件。

  按键      清脆的一声「嗒」：高频噪声做的尖锐起音 + 一个衰减很快的方波音
  按错      压低音高的闷响（与敲击声区分得开，但不刺耳）
  打完一段  一声短促的升调

**默认音量 100%**，滑块在设置里，往左拖可以调小或完全静音（拖到 0 就是关闭）。
拖动滑块时会立刻试听一声，方便判断音量是不是合适。

两声敲击音之间的差别不是音量而是音色：起音用了 highpass 而不是 lowpass，
把低频的闷响切掉，留下的才是「清脆」。如果你觉得太响，滑块拖到 60% 左右通常就够；
如果觉得还不够，说明是系统音量而不是插件音量。

## 用到的权限

只有一项：

  storage
     练习记录、统计摘要、分析数据、自定义文本与设置都写在插件自己的私有存储里
     （应用数据目录下按插件 ID 分隔的位置）。卸载插件时这些数据会一并删除。

没有申请 `network`：语料全部内置，自定义文本由你粘贴或从本机文件导入，插件不联网、不上传任何东西。
没有申请 `notification`、`filesystem-read`，也没有申请任何原生能力。

## 数据放在哪里

  record.<时间戳>.<随机>   一次练习一条，最多 50 条
  stats                    统计摘要：最近 50 次成绩、每段最好成绩、常打错的字符、总次数
  analysis                 累计按键数、按错的键、误触对照
  custom.list              自定义文本的索引（名字、字数、时间）
  custom.text.<id>         每一份自定义文本的正文
  custom.text              当前使用中的那一份
  settings                 四项设置

几个刻意的决定，以及代价：

  **记录一条一个键。** 存是一次的单文件写入，某一条损坏不会连累其他条。

  **统计与分析各存一份很小的汇总。** 打开历史或分析只需要读这一两个键 ——
  否则要把 50 份带正文的记录全部反序列化才能知道"最近十次的速度"。
  代价是信息存了两处：汇总写失败时表格会空一屏，重练一次即可补上，不会丢记录。

  **分析数据是有界的。** "常打错的字符"最多留 24 个、"误触对照"最多留 120 对、
  "按错的键"最多留 60 个 —— 都只保留计数最高的那些。长期使用不会让存储无限长大，
  而这几张表本来也只看得上前面几个。

  **记录里不存完整的错点图。** 早期设计里每条记录都带一份逐字符错误位置，
  那会让记录明显变大（每条都成了热力图数据集），换来的只是"回看某一次错在哪"。
  取舍是：记录保持小而快，错字与误触用上面那两份有界汇总来回答。

  **从不使用 clear()。** 清空历史逐个删除记录键再重置汇总，设置与自定义文本不受影响。

## 需求之外我做的几件事（以及理由）

  **判定与显示共用同一份归一化文本。** 语料里的换行在排版时会被当成词间空格，
  因此判定也必须用「换行已折成空格」的那一份。曾经拿原始文本去比，结果是打空格判错、
  段落末尾永远打不完 —— 这是本插件最隐蔽的一个 bug，所以现在只有一个来源。

  **输入层的文字是透明的，可见的字符画在它下面一层。** 输入仍由 `textarea` 承担
  （输入法、粘贴、退格、选区替换、滚轮都是浏览器原生行为），但上色由下层完成 ——
  于是光标与候选框仍然由浏览器负责，位置天然正确。

  **按容器宽度自己折行**，不交给 CSS：光标位置必须与视觉行严格对应，
  而浏览器在哪个位置折行不可预测。窗口变化（含全屏）时用 ResizeObserver 重算，
  因此打字区会铺满可用宽度，而不是留一片空白。

  **中英文都能练。** 用输入法打字时，组合（候选）过程中的内容不参与判定，
  必须等上屏才判 —— 否则中文语料每敲一个拼音字母都会被记成错误。

  **粘贴整段会被拒绝**，并且明确告诉你原因。一次最多粘一个字符。

  **"按错次数"只增不减。** 退格改对会让红色标记消失，但那次失误仍然计进准确率 ——
  否则反复退格就能把准确率刷成 100%。界面上写明了这一点。

  **计时用 100ms 刷新，速度由字符数除以实际用时算出**，与刷新频率无关；
  每敲一个键只更新字符的状态串，不会重算整篇排版。

## 已知边界

  **读屏软件用不了这个练习。** 逐字符的对错反馈是纯视觉的，隐藏层对读屏软件不可见。
  把每个字符的状态都交给读屏播报只会变成噪音。这一条不是没想到，是做不到 ——
  写在这里而不是假装不存在。

  **导入只认纯文本文件。** Word / PDF 会被识别为非文本并给出提示，请先另存为 .txt。
  这一步是"读一下看看有没有乱码"，不是严谨的格式检测。

  **不支持真正的多行排版。** 语料与自定义文本里的换行会被当作词间空格，
  段落感会弱一些；这是为了让光标位置可靠。

  **音效依赖浏览器允许播放音频。** 如果系统或浏览器策略拦住了自动播放，
  第一次按键可能没有声音（插件会在用户手势里解锁音频通道，但策略仍可能拒绝）。

  **没有排行榜、没有账号、没有云同步。** 这是本地优先的桌面应用。
